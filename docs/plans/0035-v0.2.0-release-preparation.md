`release/v0.2.0`. v0.1.1 remains the latest published release. The maintainer
will report when remote CI passes; do not wait for CI or publish during preparation.

## Acceptance criteria

- Package and lockfile versions, dated changelog, and `RELEASE_TAG=v0.2.0`
  release contract agree.
- User guidance covers flat subthreads, project search, retained source links,
  complete-project backups, schema 11, and the title-only sidebar.
- Current documentation distinguishes the candidate from published v0.1.1 and
  preserves plaintext, installation, accessibility, and platform limitations.
- Compatible dependency updates retain security fixes, full action SHA pins,
  and the supported Node/platform matrix. Deferred upgrades remain explicit.
- Review and local checks have recorded results. The release PR is left open
  for remote CI and maintainer confirmation, without a release tag or publication.

## Risks and remaining release gates

The candidate is an unencrypted alpha. Local automated and controlled-upgrade
evidence does not establish clean-machine installation, live published upgrades,
or actual desktop/assistive-technology behavior. Preserve experimental wording.
Dependency branches may need another main refresh as other PRs merge. The
release PR must incorporate the final main state and pass its required checks
before merge; publication remains a separate action.

### Dependency audit follow-up

The 2026-11-02 audit reports two moderate root advisories:
[glob cancellation bypass](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) and
[minimatch pattern amplification](https://github.com/advisories/GHSA-g3hv-75wg-m249).
There are 15 affected package entries in the full dependency tree and three in
production (`@fastify/static`, `glob`, `minimatch`), with zero high/critical
findings. The production high-severity gate passes; the audit is not clean.

The inspected static-serving path scans the trusted built `dist/client` tree
at startup with a fixed `**/**` pattern and no AbortSignal. Request URLs, project
content, uploads, and backup metadata do not supply its root or pattern, so the
documented exploit preconditions were not found in that path. Development lint
patterns and `rimraf dist` are also repository-owned. This assessment does not
patch the affected dependencies.

Follow-up ownership: repository maintainer. Review a compatible upstream update
or targeted override, then verify static serving, build/lint, cleanup, and
packaging. Patched glob 14.0.2 and minimatch 11.0.1 cross the currently resolved
dependency majors; npm's suggested static/toolchain downgrades are unsuitable.
