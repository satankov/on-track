# v0.2.1 workspace controls

Implemented and locally verified on `codex/v0.2.1`, based on the v0.2.0 tag at `8aa2096`.

## 1. Unify workspace surfaces and controls

- Remove the decorative dividers below the rail header, above its footer, between the rail and main pane, and below the conversation header. Use the history surface for the message header across Light, Neutral and Dark. Keep the timeline’s future boundary and content formatting legible.
- Remove “Local only” and its green dot. Give the footer button the accessible name “Settings”.
- Use transparent, borderless New project, Settings and Edit controls. Restore the v0.2.0 accent fills for Send, Save and other primary actions and the composer’s control colors.
- Active text-entry fields, search and composer wrappers show the native caret and have no perimeter highlight.
- Edit for projects and subthreads places Save changes at the bottom after the fields. Archive and Delete are available from the rail.
- Change `src/client/styles.css`, the rail markup in `src/client/App.tsx`, `DESIGN.md` and the interactive specimens in `branding/threadstr/ui/` together. Verify real screens in all three themes, including pointer and keyboard focus.

## 2. Expand the project shortcuts

- On hover or keyboard focus, the existing trailing shortcut area expands horizontally into **Alert → Pin/Unpin → Archive → Delete**. On touch, a tap on a named disclosure opens the same actions. The row title still opens the conversation. Keep the strip open as the pointer or keyboard focus moves between actions. Mouse-revealed shortcuts close when the pointer leaves, including after a click. Support dismissal and preserve the title’s hit area on narrow rows.
- Alert is a reversible flag on that specific project or subthread. While enabled, show the same red Alert dot used in history filters at rest and in the expanded strip, even on an empty conversation or after its last Attention label is removed. Expose its state to assistive technology. Clearing it restores the existing date-based Attention display. Toggling Alert leaves message labels and project activity order intact.
- Reuse the existing Pin/Unpin and Archive/Restore operations. Archived rows offer Restore in the Archive position and respect the existing pin eligibility rules. Apply the same shortcut pattern to editable root and child rows. Read-only examples keep their existing capabilities.
- Bind actions and delete confirmation to the clicked row ID. Name the target and, for root deletion, its subthreads in the confirmation. A canceled or failed delete preserves the data. Deleting an inactive row must preserve the current conversation and its draft unless it belongs to the deleted family. Keep errors beside the affected row and restore focus after a row moves or disappears.
- Extend `ProjectRail`, the per-project mutation guard and existing project actions in `src/client/App.tsx`. Trace the explicit Alert write through `src/client/api.ts`, the domain types and the existing server route, chat service and repository. Exercise root and child rows, archived groups, inactive targets and failed or repeated writes.

## 3. Reduce message actions and add the time preference

- Expose two toolbar buttons on editable messages, **Label** and **More** (ellipsis). Label opens the current picker. More contains Continue in subthread where available, Copy, Edit and Delete. Include Open message in history when that action is available in conversation search. Preserve copy feedback, delete confirmation and the read-only example’s ability to copy.
- Reuse the positioning and dismissal behavior of `MessageLabelPicker` in `src/client/App.tsx`. Keep only one popup open, support keyboard operation and Escape, and return focus to the trigger or the action’s destination. Hover anywhere across a message row to reveal its toolbar. Keep mouse-opened popups accessible across the row and inside the popup, then dismiss them when the pointer leaves both. Fit the menu at either end of the history viewport. Reclaim the desktop space reserved for five buttons and check own and participant messages at mobile widths.
- Add **Always show message time** to Settings → General. The default is **checked**, matching v0.2.0. When unchecked, reveal the time in the bubble’s bottom-right corner on hover anywhere across its row, keyboard focus within the message, or a tap on touch. Keep the timestamp accessible and prevent label or message movement on reveal. Apply the preference to every conversation timeline, including read-only examples. Project-wide search result metadata retains its existing format.
- Extend `GeneralSettingsWorkspace` in `src/client/Examples.tsx`, `useWorkspacePreferences`, the typed preference model and its SQLite mapping. Exercise persistence across restart, partial preference updates and failed saves alongside the message interactions.

## Data and compatibility

Use one additive schema 11 → 12 migration for the conversation Alert flag (default off) and workspace timestamp preference (default on). Constrain both booleans in SQLite and validate them at API and backup boundaries. Reuse the current migration journal and the existing preference endpoint. Existing projects, messages and timestamps retain their values.

Update `src/server/db/schema.ts`, `src/server/db/preferences.ts`, `src/server/db/project-import.ts` and `src/server/database-transfer/sqlite-backup-bundle.ts`. Keep backup format 1. Schema 3–11 bundles must pass validation before staged migration. The validator and restore path read preferences before migration, so explicitly handle the absent timestamp column for schemas 8–11. Validate both new fields strictly in schema 12. Check that older application versions refuse the newer database, and exercise upgrade recovery on disposable data.

Full backups carry both settings. Selected exports carry each included conversation’s Alert and omit workspace preferences. Replacement follows the existing initialized-preference rules, and merge retains destination preferences while copying Alerts to the remapped conversations. See [ADR 0013](../adr/0013-durable-preferences-and-project-labels.md) and [ADR 0014](../adr/0014-flat-project-subthreads.md).
