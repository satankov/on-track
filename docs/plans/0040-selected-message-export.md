# Export selected messages as readable notes

Approved implementation for `release/v0.2.1` · November 17, 2026. The implementation slice is **Selected-message export: Markdown and plain text**.

[Open the interactive mock](../../branding/threadstr/message-export/index.html) · [Desktop](../../branding/threadstr/message-export/preview.png) · [Phone](../../branding/threadstr/message-export/preview-mobile.png) · [Example Markdown](../../branding/threadstr/message-export/examples/riverside-move_move-day_2026-11-16.md) · [Example text](../../branding/threadstr/message-export/examples/riverside-move_move-day_2026-11-16.txt)

## Goal

Let someone who wasn't in the conversation understand a handful of notes: where they came from, who said what, and in what order. The same document can be pasted into an LLM or saved to disk. Start with Markdown for structured notes and plain text for email, chat, and text editors. Both are useful without threadstr.

## Context and reusable precedent

- [Message selection](../../src/client/useMessageSelection.ts) already tracks visible IDs, range selection, the 1,000-message limit and the reading anchor. [The selection bar and destination picker](../../src/client/MessageBatchControls.tsx) already replace the composer and switch the main pane without a dialog. **Copy** in that bar duplicates messages into another conversation.
- [ProjectWorkspace in App.tsx](../../src/client/App.tsx) already has the current conversation, root title, and visible notes sorted by timeline position. The [Markdown analysis](../../src/client/markdown-analysis.ts) parser already understands the app's [GFM features](https://github.com/remarkjs/remark-gfm), but its search text collapses whitespace and loses link targets. Reuse the parser setup, not that string.
- [The design contract](../../DESIGN.md) and [selection specimen](../../branding/threadstr/ui/index.html#message-selection) supply the selection bar, Edit workspace gutters, type, checked/focus states and buttons. The mock uses the application stylesheet. No shared rule changes at proposal time.

## Proposed design

1. **Select.** Open a message’s **More** menu and choose **Select messages**. Its checkbox starts checked and receives focus. Pick other messages individually, select a range, or use **Select all**.
2. **Review.** Put **Export** between Move and Delete in the existing bar. It opens **Export 3 messages** in the main pane. The project rail stays in place on desktop. The page contains Markdown / Plain text radios, one optional checkbox (**Include message labels**, off), the suggested filename, and the exact, selectable export text. The preview uses the message typeface, blank space between entries, and small differences in weight; markup characters remain visible. No popup, wizard, format menu or confirmation.
3. **Take a copy.** **Copy text** copies that format’s complete source. **Download .md** or **Download .txt** starts a local browser download of the same string. Changing format or label inclusion immediately updates both outputs and the preview. Keep the page and selection after either action. Back or Escape returns to the checked rows, reading position and Export button; Cancel in selection returns to the original draft. Do not claim a successful save to disk: download location and native prompts belong to the browser. [HTML download behavior](https://html.spec.whatwg.org/multipage/links.html#downloading-resources)
4. **At narrow widths.** Use the full-width detail pane, 16px gutters, wrapping controls and filename, a scrolling content area and a reachable action footer. Reuse native keyboard radios, square checkbox, existing focus indicators, and inline status beside the actions. No animation is required.

The mock opens on the decision screen with three of five fictional Riverside Move notes selected. Back shows the two omitted notes; After Cancel, open a message’s More menu to start another selection. It demonstrates the flow with paired sample texts, not a new production serializer.

## Format contract

| Part            | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Title           | One project title. For a subthread, use `Project / Subthread`. Omit a redundant “Main.” No export branding, prompt or front matter.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Scope           | One line with the selected count and the exporter’s time zone, captured once when the review opens. “3 selected messages” tells a recipient that this is an excerpt. Do not enumerate skipped messages, IDs or gaps.                                                                                                                                                                                                                                                                                                                                |
| Chronology      | Group by local calendar day. Spell out the month and use a four-digit year; show 24-hour times, including for messages whose time is hidden in the app. During a repeated daylight-saving hour include the numeric offsets where the displayed times would otherwise be ambiguous. Use timeline order and its existing tie-breaker, not click order. The sample uses Europe/London.                                                                                                                                                                 |
| Attribution     | Each entry begins with `09:10 · Maya`. For a null sender use **Notebook owner**, so “You” cannot be mistaken for the recipient. When labels are enabled append their user-facing names in saved display order, including transferred label snapshots; never expose internal keys.                                                                                                                                                                                                                                                                   |
| Markdown        | Title as H1, dates as H2, byline in bold. Preserve paragraphs, list nesting, task state, quotes, code and GFM tables as readable Markdown. Parse each note independently; safely close fences, resolve references locally and scope footnote identifiers so content in one note cannot consume or rename another’s. Keep body headings subordinate to the day.                                                                                                                                                                                      |
| Plain text      | Same sequence and words. Strip heading/emphasis/fence syntax; keep real paragraph breaks, indented code, nested bullets, numbered steps, `[x]` / `[ ]` tasks and quote prefixes. Flatten each table row to labeled values (e.g. `Room: Kitchen; Boxes: 4`) to read sensibly on a narrow screen. For a prose link keep `label (URL)`, once if already identical.                                                                                                                                                                                     |
| Links and files | Both formats keep user-authored portable web and email links as text or Markdown links. Use image alt text (or “Image omitted”); do not emit image embeds. Strip unsupported link targets but keep their visible text. Skip raw HTML markup as the timeline does; preserve literal code. For managed files append “1 attachment omitted.” or the plural. An attachment-only note still has a byline and omission line. No automatic filenames, paths, preview URLs or file bytes. Text a user actually wrote in a note remains part of the excerpt. |
| File            | UTF-8 without BOM, LF line endings, one final LF. Derive a portable basename from the conversation path and first selected local date, e.g. `riverside-move_move-day_2026-11-16.md`. Normalize title text; remove path separators, controls and reserved filesystem names; bound length and use `messages_YYYY-MM-DD` if empty. Append only the chosen extension.                                                                                                                                                                                   |

## Acceptance criteria

- One to 1,000 saved messages from the active selection; Export disabled with zero. Select all respects the current visible history. Collapsed notes export their whole saved bodies. The selection cannot implicitly include a parent, sibling, continuation, draft, edit buffer, search highlight or unselected neighbor. Project-wide search and read-only Examples gain no new selection capability.
- The serialized text is the only source for preview, clipboard and file. Freeze a review snapshot; if selected content, visibility or source metadata changes on refresh, invalidate it and return to selection with “Messages changed. Review your selection.” Never silently export a different body from the one on screen. Leaving the conversation clears the export state.
- Formatting takes place only on demand. For a large selection allow cancellation and keep actions disabled until the full preview is ready. Measure the maximum case (1,000 notes × 10,000 characters); avoid formatting a whole history on every checkbox change. Never fall back to a truncated export.
- Clipboard denial selects the preview and gives manual copy instructions; a download-start error is inline and retryable. Success, failure and changed counts are announced without a dialog or rereading the entire preview. The two actions remain keyboard- and touch-accessible at 320px and at 200% zoom.

## Data and migration impact

Read only the explicitly selected, already-loaded records. Build an allowlisted document model: conversation display title, local date/time, sender, saved body, optional display labels and attachment **count**. Escape generated metadata as text, including title and sender punctuation or line breaks. Never render a preview as active HTML, follow a link, or fetch an attachment. The resulting plain file or clipboard belongs to the user. No new route, server write, database migration, backup-format change, preference, telemetry, permission request on entry, or production dependency is proposed. Discard the snapshot on exit; release Blob URLs after dispatch.

## Phases and test plan

1. **Lock the formats.** Add a pure client serializer (proposed `src/client/message-export.ts`) plus fixture tests. Use the two linked examples as golden files. Cover a main and a child, one/multiple days, reversed selection, tied times, Unicode, transferred labels, destination-bearing links, reused references, incomplete fences, task lists, tables, quoted text and a file-only message. Check filenames, markup in metadata, inert image/link output and no excluded content. Run `npm test -- src/client/message-export.test.ts`.
2. **Connect the flat workflow.** Extend the local UI stages in `useMessageSelection.ts`, `MessageBatchControls.tsx` and `App.tsx`; add a compact `MessageExportWorkspace.tsx` and scoped styles. Do not widen the server mutation union. Component tests cover entry from the message menu, range and sparse selection, toggling format/labels, stale snapshot, focus/draft restoration, copy denial and retry. Check the same string reaches both output actions. Run `npm test -- src/client/App.test.tsx src/client/message-export.test.ts`.
3. **Qualify in the real app.** Extend `e2e/message-batch.spec.ts` to compare downloaded UTF-8 bytes and suggested names against the preview, navigate back, and verify that no backup, attachment, or external request was initiated by export. Check wide/narrow, three themes, keyboard, touch, zoom, forced colors and max-size responsiveness. Run `npm run test:e2e -- e2e/message-batch.spec.ts`, review the file/clipboard boundaries, and run `npm run verify`. Update the selection section of `DESIGN.md` and the cookbook when the feature is implemented.

## Risks and non-goals

A reader can still learn sensitive details that were written into a selected message or its project title; the preview is the review boundary. A browser may prompt for a download or reject clipboard access. The text export is an excerpt; Settings backups remain the way to restore projects and actual files. Defer PDF (pagination/layout), HTML (active document handling), JSON/JSONL (machine consumers), rich clipboard, cross-conversation selection, attachment bundles, and direct sends to people or an LLM.

## Mock verification

Chromium and WebKit both downloaded each sample with the expected filename and exact fixture bytes. A clipboard stub received the same text; simulated denial exposed a selected read-only field containing the complete text, including its final newline. Checks also exercised reverse-order selection, Back/Escape focus, an unchanged draft. Three themes at 1440, 1024, 390 and 320px and a 720 × 450 constrained viewport retained reachable actions without horizontal overflow. No external requests occurred. Prettier, ESLint, JavaScript syntax and local document links passed. This evidence covers the fictional mock only; the real-app checks above belong to implementation.

## Implementation

The released dependency tree already includes the MIT-licensed `remark-stringify` 11.0.0 through `remark-gfm`. The client declares that same locked version directly to serialize normalized Markdown. Formatting runs on demand, in a dedicated same-origin worker for selections over 32 messages or 24,000 source characters. Closing the preview or changing its options cancels the previous job.

The built app produced both Riverside Move example files byte for byte. Light, Neutral and Dark layouts were checked at 1440, 1024, 390 and 320px and a 720 × 450 constrained viewport. Keyboard operation also passed in forced colors. On this Mac, Chromium rendered a synthetic selection of 1,000 notes with 10,000 characters each in 6.6 seconds from opening Export. The download matched all 10,030,093 preview characters. Back during preparation returned to the checked rows in 4.0 seconds, including restoring the large timeline.
