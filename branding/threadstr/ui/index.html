07 / States & feedback

Flat, with visible affordances.

1px focus outline, 1px offset. A focused field may have a line; an idle field stays flat.

08 / Responsive rules

Adapt the structure, preserve the language.

Desktop / above 760px

Room for the workspace

Persistent sidebar. 840px settings content. Triple left inset. Top Back/Save actions. Vertical history filters.

Narrow / 760px and below

One pane at a time

16px settings gutters. Horizontal settings navigation. Single-column theme choices. Full-width input and reachable toolbar.

At ≤960px, message actions remain visible. Use 600px chat container rules when the workspace itself is narrow. Keep long labels, keyboard access, local table scrolling, and error messages usable.

09 / The next UI change

Reuse before inventing.

  1. Read DESIGN.md and choose the nearest existing component family.
  2. Use its typography, spacing, semantic tokens, states, and accessible markup.
  3. Check all three themes, keyboard focus, long content, narrow widths, and affected error states.
  4. Update the specification and this specimen only when a shared rule intentionally changes.
Legacy CSS is not the default recipe

Generic .text-input, .accent-option, .button-quiet, and .button-danger retain some older borders. The current settings classes override them. Use the scoped flat patterns; do not copy the first matching CSS declaration or refactor unrelated legacy rules during another task.
